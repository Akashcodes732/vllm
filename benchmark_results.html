🚀 Real-World Serving Verification: Threshold Dispatched MMA Delivers +14.2% Throughput & -36.7% P99 Tail Latency
The end-to-end serving runs on Gemma-4-26B-A4B-it validate both architectural mechanisms implemented in this PR:
  • Threshold Behavior (m_size < 4 vs m_size >= 4): At Concurrency 1, the engine processes single query tokens (m_size = 1), correctly routing to the Row-VSX path and achieving throughput parity (7.51 vs 7.58 tok/s), preventing the 15-20% regression of pure MMA. At Concurrency 4 (m_size = 4), the dynamic threshold triggers the 32x4 MMA kernel, accelerating output throughput to 14.95 tok/s (+14.2% gain) and completing the benchmark 38.95 seconds faster (-12.4% duration).
  • BF16 Probability Cache Halving: Slashing intermediate probability storage from 32-bit float to 16-bit bfloat16 eliminates memory bus saturation under concurrent load. This compresses tail latency spikes dramatically: P99 inter-token latency drops from 413.60 ms to 261.97 ms (-36.7%) at Concurrency 4, from 467.63 ms to 337.24 ms (-27.9%) at Concurrency 8, and from 648.32 ms to 510.04 ms (-21.3%) at Concurrency 16.

Every vector SIMD backend in vLLM maintains FP32 intermediate probabilities between Softmax and PV GEMM. By setting using prob_buffer_t = float; across all models and head dimensions, PowerPC VSX eliminates millions of unnecessary conversions per inference step.
